# Bahandi Staff Platform — план backend-реализации

Статус: Workday MVP реализован 2026-08-12; дальнейшие пункты отмечены ниже. Этот документ — постоянная точка возврата для
реализации Workday MVP. Подробные API-контракты фиксируются рядом с кодом в
`back/API.md` и тестах.

## Цель MVP

Первый рабочий сквозной цикл:

`график -> публикация смены -> отметки входа/перерыва/выхода -> табель ->
корректировка -> подтверждение менеджером -> уведомление сотрудника`.

Параллельно должны работать задачи/чек-листы. Текущая система списаний остаётся
без регрессий и входит в раздел «Операции».

## Архитектурные решения

- Сохраняем модульный Flask-монолит и единый API для Web/iOS/Android.
- SQLite — для разработки и тестов; PostgreSQL — целевая БД пилота.
- Backend — источник истины; `localStorage` остаётся только UI-кэшем.
- Даты хранятся в UTC, у точки есть timezone.
- Все согласования имеют явную state machine, audit и optimistic version.
- Повторяемые мобильные действия используют idempotency keys.
- Нет постоянного трекинга геолокации.
- Доход всегда маркируется `preliminary` или `final`; списание не создаёт
  автоматическое удержание из зарплаты.

## Этапы

### Реализовано в первой итерации (2026-08-12)

- Миграция Alembic, расширенные роли, store scopes, permissions, feature flags и audit.
- Смены, назначения, публикация, открытые смены и запросы сотрудника с проверкой пересечений.
- Append-only time events с idempotency, state machine, табели, корректировки и решения менеджера.
- Задачи/чек-листы, проверка менеджером, обращения, новости и универсальные уведомления.
- `/api/platform/bootstrap`, `/api/manager/today` и подключение employee `/app` к backend.
- Payroll/HR оставлены выключенными feature flags до появления официальных источников данных.
- Добавлен server-backed workflow сервисов сотрудника: прогресс обучения,
  запросы документов и заявки на отсутствие. Баланс отпуска помечается
  `preliminary`; официальные HR/payroll-источники по-прежнему не подключены.

## Обязательные проверки

- Unit: permissions, state machines, пересечения, timezones, расчёт табеля.
- API: каждая роль, чужая точка, деактивированный пользователь, неверный статус.
- Concurrency/idempotency: открытая смена, решение менеджера, повторный clock-in.
- Migration: upgrade существующей БД и чистая установка.
- Regression: существующие auth/writeoff/webauthn/uploads/admin тесты.
- Frontend: store/API tests, production build и критический e2e-сценарий.

## Definition of Done пилота

- Данные `/app` приходят с backend, кроме модулей, выключенных feature flag.
- Состояние одинаково на двух устройствах.
- Менеджер видит и обрабатывает реальные запросы.
- Нет пересекающихся/дублирующихся смен и двойных time events.
- Каждая корректировка имеет автора, причину и audit trail.
- Данные разных точек изолированы.
- Уведомление ведёт к сущности и следующему действию.
- Списания работают без регрессий.
- Модуль можно отключить без redeploy.
